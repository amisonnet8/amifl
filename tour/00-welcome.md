## AmiFLとは何か

AmiFLは「AWK/Perlの系譜だが、Perl的な乱雑さを避けた汎用データ処理特化言語」です(`amifl-spec.md` §0)。データを読み込み、変形し、書き出す——そういうプログラムを、行き当たりばったりの寄せ集めではなく、**一貫した設計原則**の上で書けるようにすることを目指しています。

AmiFLは**静的型付け**言語です。値の種類は常にコンパイル時に確定し、実行時の動的ディスパッチはありません(§0)。`Int`と`Int64`は同じ型ですが、`Int32`と`Int64`は別の型として扱われ、暗黙変換は一切起きません——これがAmiFLの最初の大きな性格です。

## 7つの設計原則

AmiFLの設計は、次の7つの原則に一貫して立ち返って作られています(§1)。このツアーを読み進めると、あらゆる構文の背後にこの原則があることに気づくはずです。

1. **式指向・文の排除**——プログラムは式の並びだけでできています。`if`も`switch`も`let`も、すべて値を持つ式です。
2. **暗黙変換の排除**——サイズや符号の違う数値型は相互に変換しません。異なる型どうしの`==`もコンパイルエラーです。
3. **1つの仕組みで足りるものを2つ用意しない**——多次元配列は`Array`のネストの糖衣、`x[i][j]`は添字の連鎖、パターンマッチは`switch`の拡張——専用構文をむやみに増やしません。
4. **ユーザー拡張ポイントを絞る**——オーバーロード無し、ユーザー定義の多相拡張無し、可変長引数無し、カリー化無し、`struct`/`enum`にメソッド無し。
5. **グローバル可変状態の排除**——トップレベルの`let`は禁止です。
6. **戻り値は常に単数**——複数の値は`Tuple2[T, Error]`のような統一された形に包みます。
7. **明示性 > 簡潔さ**——可変長引数・名前付き引数は提供しません。

この7原則は、このツアー全体を通じて何度も顔を出します。「なぜこの構文はこう書くのか」に迷ったら、まずこの7原則のどれかに立ち返ってみてください。

## Hello, AmiFL!

`hello.aml`という名前で、次の内容のファイルを作ります。

```amifl
fn main() -> Int {
    print("Hello, AmiFL!")
    0
}
```

`main`は他の`fn`と全く同じ構文で書く、AmiFLの唯一のエントリーポイントです(§14)。戻り値の`Int`はプロセスの終了コードになります——`return`という専用のキーワードは無く(原則1)、関数本体の**最後の式**がそのまま戻り値になります。ここでは`print(...)`(戻り値`Unit`)の次に置いた`0`が、`main`全体の戻り値です。

実行するには次のようにします。

```sh
$ amifl run hello.aml
Hello, AmiFL!
```

`amifl run`は「コンパイルして即座に実行する」コマンドです。`amifl build`で実行ファイルを作ることもできます(コマンド一覧は9章、および`amifl-spec.md` §16.2を参照)。

## AmiFLのコンパイルパイプライン

AmiFLのソース(`.aml`)は、`AMIVM-IR`という中間表現を経由してGoのコードへ変換され、最終的にネイティブな実行ファイルになります(§0)。

```
AmiFLソース (.aml) → AMIVM-IR (.ir) → Goコード (.go) → 実行ファイル
```

この工程の細部を普段意識する必要はありませんが、AmiFLがなぜ「静的型付け言語」であることにこだわるのか(意味検査を全てコンパイル時に終わらせ、実行時エラーを最小化する)を理解する助けになります。
